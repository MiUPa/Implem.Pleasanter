# Kumitate 全部入り Docker（クイックスタート）

データベース（PostgreSQL）同梱のオールインワン配布です。
**コマンド1つで起動し、面倒な初期設定はすべて自動で済みます。**
試用・評価・小規模利用向けの構成です。

## 前提

- Docker がインストールされていること（Docker Desktop、または Docker Engine + Compose v2）
- それだけです。DB のインストールや設定ファイルの編集は不要です。

## 起動

このフォルダ（`docker-compose.yml` がある場所）で実行します。

```shell
docker compose up -d
```

初回はイメージのダウンロードとデータベース初期化のため、数分かかります。

## 開く

ブラウザで以下にアクセスしてください。

```text
http://localhost:8080
```

初期ログイン:

| ログイン ID   | パスワード |
| :-----------: | :--------: |
| Administrator | pleasanter |

初回ログインではパスワード変更のあと、そのまま**初期セットアップウィザード**が開きます。言語・タイムゾーンの確認と、使い方のイメージがつかめるサンプル（タスク管理表）の読み込みまで、その場で完了できます。ウィザードは初回だけ表示されます。

## 仕組み（参考）

3つのコンテナで構成されています。

| コンテナ       | 役割                                                                 |
| -------------- | -------------------------------------------------------------------- |
| `kumitate-db`  | PostgreSQL。データは Docker ボリューム `kumitate_pg_data` に保存され、再起動や更新でも消えません |
| `kumitate-init`| DB の初期化・定義更新（CodeDefiner）。起動のたびに自動実行され、終わるまで本体は起動しません |
| `kumitate`     | Kumitate 本体                                                         |

## 設定変更（任意）

ポートやパスワードを変えたい場合だけ、`.env.example` を `.env` にコピーして編集してください。
`.env` が無くても既定値で起動します。

- 既定の DB パスワード（`kumitate` など）は試用向けの値です。**外部に公開する環境では、初回起動前に必ず変更してください。**
- パスワード類は初回起動時に DB へ設定されるため、変更は初回起動前に行ってください（起動後の変更は DB 側の変更も必要になります）。

## 更新

新しいイメージを取得して再起動するだけです。DB の定義更新は `kumitate-init` が自動で行います。

```shell
docker compose pull
docker compose up -d
```

## 止める

```shell
docker compose down
```

データはボリュームに残るため、再度 `docker compose up -d` すれば続きから使えます。

## データをすべて消す

```shell
docker compose down -v
```

ボリュームごと削除され、データベースは初期状態に戻ります。元に戻せないためご注意ください。
